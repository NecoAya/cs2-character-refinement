# 工作流程与任务示例

## 新角色完整制作

按 [阶段合同](../references/stages.md) 执行 11 个阶段：

```text
资产审查 → 造型材质 → 官方骨架/角色绑定 → 第一人称手袖
  → 物理 → 受击框 → 单模型持枪 → 减面/贴图优化
  → 编译 → 成品回归 → 依赖包交付
```

对应阶段 ID：`intake → appearance → rig → firstperson → physics → hitboxes → holding → optimization → compile → validate → package`。

先建立源与工具清单、单位/坐标、选装、原材质层与表情目录。真实输入、参数和模型记录在角色工程保存，技能仓库只保留通用模板。造型确认后适配官方动画骨架和角色变形骨架；官方骨与约束检查见 [骨架专题](../references/rig-and-constraints.md)。

第一人称使用用户手源并制作当前衣服袖套，验证视角分组、腕口和附件绑定。物理按根/中段/末端配置，受击框与持枪检验实际姿态；这些稳定后再减面和压纹理，以保护弯折和近景外观。

编译回读网格、骨架/约束、物理、材质与依赖，再交付用户测试。每阶段保存独立结果与关键真实产物，后续更新自己的清单，不改历史阶段。执行器和状态见 [runner](runner.md)。

用户选择检查点时提供对应预览或候选，并记录真实反馈。自动模式不强制逐步问确认；必要输入不足时完成独立工作，说明剩余条件。离线完成与游戏待测可以同时存在，不以阶段状态补出实机通过。

## 修改影响与重跑

| 改动 | 需要复验的范围 |
|---|---|
| 颜色层、金属/粗糙度、AO | 材质输入、实际编译像素、依赖、近景与预算 |
| 骨架、父级、bind、约束 | 第一人称、持枪、物理、挂点、hitbox、表情及最终成品 |
| 局部物理 | 目标控制、碰撞、编译差异、非目标保护、动作观察 |
| 减面、UV、顶点重排 | 拓扑、UV、法线/切线、蒙皮、形态键、动态弯折及全部下游成品 |
| 换装选项或表情控制 | 当前选项映射、组合、依赖、物理状态、运行接口及恢复 |

复用既有产物时，记录来源、哈希、复用范围和仍需重验的项目。执行器不会自动推断阶段依赖，作者必须把这些要求纳入当前合同。

## 局部迭代

```text
锁定真实输入与任务目标
  → 确定允许差异和保护项
  → 选择一项可检验的假设
  → 从明确基线制作独立候选
  → 源、导出、编译与依赖回归
  → 交付有范围的观察方法和恢复对象
  → 记录结果，接受或恢复
```

局部任务不要求每次重做整个人物。诊断请求先给出原因和证据；实施请求在已授权范围内修改，并重验受影响的下游。真实工程日志和接受记录留在用户工程中，不提交到技能仓库。

## 示例一：预览只显示碰撞形状

先确认当前查看器是在显示渲染网格、物理形状还是受击框，再检查网格组选择、实际模型路径和材质依赖。缺失模型、隐藏的渲染组和查看模式错误是不同问题，不能由一个占位外观直接判断几何损坏。

在明确目标后，只调整相关显示或依赖设置，保留网格和绑定。重新读取成品并使用相同查看条件复查；查看器正常仅证明该检查范围，游戏装载仍单独确认。

## 示例二：减面后表情变形异常

检查基础网格和每个发布变形目标的对应关系，确认顶点重排、焊接与简化是否同步作用于 Morph/Shape Key。对比 neutral、单目标极值和常用混合，查局部误差、嘴唇闭合、眼皮与材质边界。

若没有可靠的映射算法，先保护受影响的面部拓扑，在其他部位实现预算目标。记录各级 LOD 的显示成本和全部存储资源，不能只用静态预览或 ZIP 大小宣布优化完成。见 [表情扩展](../references/expressions.md) 和 [预算方法](../references/materials-and-optimization.md)。

## 示例三：阶段命令成功，但产物缺失

检查执行器日志、实际 argv、工作目录、成功标记和输出合同。命令退出零或提前打印成功标记，都不能证明编译资源已生成。成功标记应由 adapter 在实际检查通过后输出。

修正具体命令或合同后建立符合配置要求的新候选，不伪造输出、不修改已有 receipt 哈希来继续。核验源、导出、编译资源和引用依赖；记录哪些检查完成、哪些仍等待游戏观察。见 [执行器](runner.md)。

## 示例四：更换导出器后握持位置偏移

核对两个导出器的单位、轴约定、bind 变换、必要官方祖先和约束输出。先按名字比较源与编译骨架，再判断是坐标转换、裁剪、约束求值还是角色比例造成偏移；不要仅因索引变化就重刷全部手部权重。

一次只调整一个已证实的问题，在支持的武器和站立/蹲下姿态中检查手与武器关系，并分别记录第一人称和第三人称范围。编译成功与静态握点正确不能代替完整动作验证。见 [骨架与约束](../references/rig-and-constraints.md) 和 [持枪与受击框](../references/holding-and-hitboxes.md)。

## 停止与交付

未解释的非目标差异、缺少必要源绑定、候选身份不明且会影响结论、或需要超出授权的外部写入时，停止相关修改，继续不受影响的只读检查。需要用户游戏观察时交付可逆候选和明确的动作清单，不把等待观察写成全部通过。

完整包或补丁均明确依赖和底包，附已知限制、恢复对象及覆盖范围。整体观感接受只按实际范围记录，不扩展为所有武器、碰撞、性能和根因均已验证。
