# 快速开始

## 先准备什么

至少提供当前目标和实际使用的文件。完整诊断通常需要以下输入，缺项时说明限制，仍可先完成其他检查：

| 输入 | 用途 | 缺失时的边界 |
|---|---|---|
| Blender / Unity / FBX / DMX 与 VMDL | 制作造型、绑定、材质及导出 | 仅有成品时未必能安全重建作者意图 |
| 当前官方动画兼容模板与用户基础手 | 核对官方骨/约束、制作第一人称 | 可先做资产审查，相关制作等待真实输入；仓库不附带手资产 |
| 实际编译模型及依赖 | 查真正进入游戏的结果 | 仅源码检查不代表成品一致 |
| 已接受基线和候选身份 | 做回归和回退 | 不把“最新”当“已接受” |
| 用户反馈或视频 | 判断动作、受光与观感 | 无截图也能先查静态数据，但观感仍待测试 |
| 预算与禁止改动项 | 限定优化与修复范围 | 不擅自降低外观、取消运动或覆盖安装目录 |

将当前项目的任务约定记录到 [任务模板](../examples/task-contract.json) 的副本中。副本应放在角色工程，不把真实路径或资产提交到本技能仓库。

## 安装到个人技能目录

本仓库可公开克隆。已安装 Git 时，Windows PowerShell 示例：

```powershell
$skillDirectory = Join-Path $env:USERPROFILE '.agents/skills/cs2-character-refinement'
if (Test-Path -LiteralPath $skillDirectory) { throw '目标目录已存在，请先检查已有技能，勿直接覆盖。' }
git clone https://github.com/NecoAya/cs2-character-refinement.git $skillDirectory
```

个人目录 `.agents/skills` 与项目目录 `.agents/skills` 都是当前官方文档列出的本地发现位置。不要同时安装多个同名副本，以免使用时不清楚加载了哪份。[OpenAI 技能文档](https://learn.chatgpt.com/docs/build-skills)

也可以下载完整仓库后，将目录作为一个整体放入技能目录。不要只复制 `SKILL.md`，否则参考与脚本链接会失效。下载、个人副本的使用及修改仍需遵守 [来源与许可说明](../SOURCE.md)，不因公开可见而自动获得未授予的权利。

## 项目内使用与免安装阅读

希望只在某个角色工程启用时，把完整目录放在该工程 `.agents/skills/cs2-character-refinement`。遵守该工程现有规则，不覆盖其同名目录。

不想安装时，直接给 Codex 这份 `SKILL.md` 的实际路径并明确要求读取。GitHub 发布和本地安装是不同步骤；存在远程仓库不会自动让所有会话加载技能。

## 调用

完整制作：

```text
使用 $cs2-character-refinement 从我给的原始角色资产开始转模。
按完整流程自动推进，第一人称使用我提供的基础手。
请保留表情数据，逐阶段记录文件、哈希、检查及待测项。
```

指定检查点：

```text
使用 $cs2-character-refinement 制作角色。
造型、第一人称和物理三个阶段先给我看；其他已明确部分自动执行。
```

局部诊断或修改：

```text
使用 $cs2-character-refinement 诊断当前模型的次级运动问题。
先检查实际蒙皮与控制关系，不要实施改动。
```

```text
使用 $cs2-character-refinement 修复指定材质的颜色层遗漏。
请先核对源材质和最终编译输入，保护其他面组、骨架和物理。
制作独立候选，保留当前接受版。
```

也可以自然语言提出匹配的问题，由支持该方式的宿主选择技能。使用接口、触发方式和发现行为以实际宿主为准；没有出现时检查目录，再按官方说明重启应用。[OpenAI 技能文档](https://learn.chatgpt.com/docs/build-skills)

## 更新

在已克隆的技能目录先检查 `git status --short`，确认自己的改动，再使用 `git pull --ff-only`。发生分叉或本地修改冲突时停止并处理，不使用强制重置丢弃修改。

更新技能不会修改已经交付的角色候选；模型输入、验证记录和版本回退仍由角色工程维护。

2.x 沿用原技能 ID，但加入完整流程和脚本。用户素材仍放在角色工程，不复制到技能目录。已有其他转模技能可保留；本技能已包含所需制作阶段，无须再强制串联另一个技能。

调用脚本时先进入技能仓库根目录。将真实资产、角色工程、日志和快照放在技能目录之外；例如 `--source ../character-assets --workspace ../character-project`，外部手清单可使用 `../hand-assets/manifest.json`。这些是路径示例，按实际位置替换；源必须已经存在，输出必须是新的目录且不能位于源内。完整命令和阶段恢复见 [执行器](runner.md)。

## 移除

先确认应用实际加载的是哪个同名技能。若只需停用，按宿主设置操作；需要移除文件时只针对明确的技能目录，保留自定义修改和用户工程。本仓库不提供自动清理用户目录的命令。
