# 阶段合同：从源资产到交付

这些是实际制作步骤，不是自动盖章的检查表。新角色模式中的 `agent` 阶段由执行本技能的 Codex 完成；可复用操作实现成 CLI adapter 后替换该阶段的 argv。每阶段的 result.json 必须列出真实产物路径、SHA256、参数、检查数值和限制，并把关键产物加入执行器 outputs，才能获得文件快照和防篡改恢复检查。

| 阶段 | 实际工作 | 交付/验证 |
|---|---|---|
| intake | 枚举 Unity/FBX、服装、头发、耳尾、眼睛/妆容 PSD/PNG、参考 VPK；读取本地工具能力；确定单位、朝向、默认 shape key、选装 | source_manifest、工具版本/哈希、选择配置、骨骼/网格/材质目录。原始输入只读 |
| appearance | 导入并保留编辑骨架；统一衣服和身体比例；贴图的 alpha/mask、色彩空间、妆容层合成；独立眼睛材质；眼镜贴脸和镜腿定位；按组件移除装饰 | 编辑场景、正侧背与脸部预览、源→输出材质映射、删除组件清单；检查 UV 不因合并丢失、alpha 与背面法线正确 |
| rig | 按 [骨架与约束](rig-and-constraints.md) 保留原生 CS2 动画骨架和模型自身变形骨架，明确 local/world/bind 坐标转换；逐骨映射、约束及固定长度手臂解算 | bone_map、rest 矩阵、导出 DMX、动画采样报告；官方骨架与祖先完整、约束顺序有效、编译依赖保留、权重归一、索引合法、无孤立变形骨、手臂长度稳定；不能只检 T-pose |
| firstperson | 按 [第一人称](firstperson.md) 使用用户提供的基础手，分离第三人称身体、第一人称手、可开关袖套；保留指甲几何并独立材质；腕部衔接；腿/鞋保留合适 character pass | TP/FP render group 与材质规则、手/袖 DMX；检查官方动画骨/约束与编译映射、第一人称视野、腕缝、指甲、UV、权重；临时预览不代替游戏判定 |
| physics | 按 [物理响应调校](physics.md) 检查参考 PHYS、源 ModelDoc 和实际蒙皮；根部随身体、末端模拟；分部件调整弯曲、回正和动作驱动；稳定后再决定静态风场 | 每条链的 anchor/末端/参数/碰撞器配置及差异；根点质量和锁定检查；转视角、慢走、快跑、停止、蹲下分开记录；用户要求射击抖动时另验驱动与原地射击，不能以编译通过代替 |
| hitboxes | 少量贴合而适度留余量的 cstrike 胶囊/球；每手一球；两侧上臂、前臂；大腿/小腿/脚；适度扩头与躯干。选实际变形骨或正确 solver 骨并换算端点局部坐标 | authored hitbox 配置、伤害组、骨绑定和服务端依赖清单；端点往返换算、动画姿态采样；编译后全局 remap 与骨名逐项检查；不能只看客户端框 |
| holding | 一个 player model 使用官方动作。武器位姿与角色右手保持一致，左手按真实臂长求解；站立和蹲下、AWP/AK/短枪都采样 | 一个 VMDL、武器/背枪挂点配置、左右臂长度和目标距离报告；检查第一次切模型/重生，不能依赖购买另一把枪初始化 |
| optimization | 完成外形/绑定/持枪后再优化。删除不用的 render group/组件；按一套衣服算预算；先压不显眼贴图，再谨慎简化衣服/头发，保护脸/手/轮廓/UV/关节与动态弯折区 | 前后 model、材质/贴图闭包、三角形/分辨率/压缩格式/drawcall 等独立数字；几何表面与变形误差、近远图；不能只以包大小推断渲染性能 |
| compile | 在唯一 addon 目录编译，搜错误/警告，检查实际输出；需要时使用经过验证的 full/metadata 成对编译 | 完整日志、原始编译资源、装配记录、最终资源。compiler-only 依赖不出现在交付 hitbox 集；不能手改骨骼 flags/index |
| validate | 检查最终 compiled model 的骨骼、remap、网格、材质、动画、受击框、约束、PHYS；脚本的套用/恢复/重生/外部改模取消逻辑做 mock | 精确比较报告；不是“编译成功”四个字。区分离线通过、用户通过、待实测 |
| package | 递归解析 RERL 收集模型/材质/纹理；外部基础动画单列；VPK CRC 与逐文件读回；只打当前版本 | 一个角色 VMDL 的依赖包、必要 JS 编译结果、检查命令、配置/输入锁、快照与回退说明；不带所有历史版本 |

## 全自动、检查点和定制

自动模式：配置已明确的部分连续执行，阶段快照自动保存。对新角色由 Codex 执行 authoring，运行器自身不会替代 Blender 工程制作。仅当必要选择无法从素材/请求推断时才询问，并继续其他独立工作。

检查点模式：建议 appearance（造型）、firstperson（手袖）、physics（效果）、hitboxes（伤害）、holding（持枪）、package（交付）。用户选择哪些就停哪些，不强制全部。需要画面验证的检查点先给预览/候选包，不能只给抽象参数。

定制：在新配置写具体目标、目标区域、保护项及可观察的验收标准，例如局部颜色调整不改几何，或选定运动部件改变响应而其他部件保持。把愿望落实成有输入/输出的 adapter 或实际 authoring 修改，记录差异。改变骨架会使下游 firstperson、physics、hitboxes、holding、compile 全部需要重验；换瞳色通常只涉及 appearance、材质编译和依赖包。执行器新 run 不自动推断依赖，作者要明确标注复用来源与需要重跑的阶段。

## 多衣服/瞳色/妆容/耳尾扩展

读取 [换装扩展](wardrobe.md) 和 `assets/wardrobe.template.json`。在 intake 记录选项和默认组合；appearance 保留网格/材质切换边界；rig/physics 绑定每个选项的骨架、遮挡与物理配置；firstperson 同步袖套；optimization 同时预算单套显示开销、全部选项总包和新增选项的增量；compile/validate/package 处理真实分组映射、切换逻辑和组合检查。

新模板 `request.wardrobe.mode = reserve` 只要求保留扩展点并交付清单，不自动制作用户未提供的衣服或宣称已有游戏菜单。`implement` 才实现实际切换；两者都考虑共享资源与体积。新增网格组可能改变编译块布局和骨骼映射，后处理必须按当前模型重新验证。

## 表情、嘴型与眨眼扩展

读取 [表情嘴型扩展](expressions.md) 和 `assets/expressions.template.json`，处理 `request.expressions`。默认先审查并保留原始形态键/Morph、面部骨骼或嘴部网格选择，不沿用旧静态导出的统一清除 shape key 操作。每阶段维护自己的 expressions.json；真正实现时补齐编译控制器映射、运行时驱动与组合验证。减面/合并/顶点重排要同步所有变形目标，表情数据和嘴部备选网格计入同一总包预算，不能只测试 neutral。
