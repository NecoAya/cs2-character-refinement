# 诊断与编译原则

完整流程以 [阶段合同](stages.md) 为入口，骨架与手模问题先读 [官方骨架与约束](rig-and-constraints.md)。

这里保留可迁移的经验，不保留角色专用版本与补丁算法。具体数字由每个项目的源数据和编译结果决定。

## 受击框

- 先检查服务端与模型约束配置。使用约束生成角色姿态时，服务端关闭约束可能令客户端外观与实际伤害骨架不同。
- 服务端框决定伤害；客户端框对齐不是伤害验证。先清除两端叠加显示，再逐端观察，避免把两端的同一个球误认成两个 hitbox。
- 换绑定骨时经旧骨 local → bind world → 新骨 local 换算端点。仅改骨名会导致错位。
- 伤害不正确时查实体/队伍、真实血量、伤害组、动画、约束与骨依赖；不先靠盲目扩大框或添加手指框覆盖。

## 物理

首次制作或局部调校读取 [物理响应调校](physics.md)。弯曲柔软度、回正速度、低速动作输入与射击触发分别处理，避免把所有问题归为刚度不足。

- 根部跟随动画，远端摆动；锁死整条链会让摆动也消失。先固定根部和运动稳定，再决定静态风场。
- 带蒙皮的主体骨同时参与物理碰撞驱动时，需排查反馈。可评估无蒙皮权重的独立跟随叶骨，不让模拟反向写回骨盆、头或大腿姿态。
- 对比参考应看单位、骨长、局部基底、静态/动态节点和实际权重，不能只抄刚度、阻尼。
- 转视角、快跑、停止、蹲下、隐藏/切换物理选项分别验证；离线采样不等价于完整运行时动画图。

## 编译与装载

- 由编译器生成骨骼裁剪/排序/flags/remap；不要直接修改编译数据里的某几个索引或标志。
- 若某项目需要临时依赖标记或成对编译后处理，必须先证明实际块布局、真实 hitbox、各网格骨名映射和 buffer 不变，再提供项目专用 adapter。通用流程不预设 MDAT 数量、骨数或 hitbox 总数。
- 编译器退出 0 不代表无错误，检查日志和实际输出。Blender 脚本需在所有断言通过后打印成功标记。
- 使用独立命名的 addon/工作目录，保护原有共享材质。编译器可能连带重编依赖；源工程历史副本未必等于当前接受的 runtime 文件，应锁定真实输入。
- 新模型先预载、确认驻留再应用。脚本初始化、切枪、重生和恢复逻辑自洽，不依靠切到另一个模型或购买别的枪触发初始化。

## 资源与预览

材质/纹理按 RERL 依赖闭包收集，外部基础游戏动画单列。每个 MDAT 可能涉及多组 buffer，按实际块索引解析。比较多套服装时计共享资源一次，区分估算选中块大小和真实重编包。

查看器出现绿色胶囊人时先检查物理显示、网格组选择和材质依赖；渲染网格、物理形状和伤害 hitbox 是不同的显示数据，不能仅凭颜色断定未编译或加密。
