# 表情、嘴型与眨眼扩展

本篇与 [阶段执行器](../docs/runner.md) 的配置模板配套；实际源数据、作者产物和运行控制证据进入当前工程。

此处先定义可继续完善的制作接口，和换装共存。配置存在不代表游戏内已经能切换表情；本工作流尚未实现对应 runtime adapter。

## 先识别模型用哪种方式

| 源结构 | 实现方向 | 注意 |
|---|---|---|
| Unity/FBX BlendShape、Blender Shape Key，或 Source 2 已编译 Morph | 保留 Basis 和变形增量，建立逻辑表情 ID→源目标→编译后的控制器映射 | 需要核实导出器、编译器、目标游戏与运行时接口的实际支持，不能把 Unity 目标名直接当成 CS2 控制命令 |
| 下颌、嘴唇、眼皮等面部骨骼 | 保留面部骨与局部变换，用约束/动画控制 | 不改变身体、持枪和 hitbox 骨架的既有语义；检查和 Morph 混合时是否重复变形 |
| 不同嘴、牙齿、舌头或表情附件是不同网格 | 通过同模型内的网格组控制显示，和换装的稳定选项 ID 机制衔接 | 这是网格切换，不能假设可连续插值；张嘴要检查口腔遮挡、牙齿与舌头穿出 |

一种模型可以混用这些方式。源模型没有嘴型时，应标出需要制作的目标，不能把静态嘴巴自动命名成已有表情。

## 数据保留和控制入口

复制 `assets/expressions.template.json`，按 `reserve`（保留与审查）或 `implement`（实际可控）执行。`controls` 的每条记录至少包含稳定 id、channel、representation、source_targets、default、range、compiler_binding、status；原始名字另存，不以导入器/编译器的数组下标作为永久 ID。

- `emotion`：高兴、生气等整体表情，可由多个目标组成。
- `mouth`：张嘴、闭嘴和已有口型；逻辑口型名称不是引擎 API 名称。只登记源资产确实存在或后来真实制作的目标。
- `blink`：左右眼眨眼，允许组合；需要时再实现自动眨眼。
- neutral 为可恢复的默认状态，控制器有有效范围、冲突/叠加规则。整体表情如果也驱动嘴或眼皮，要说明与 mouth/blink 谁覆盖谁、谁相加，避免双重驱动。
- 衣服/瞳色/妆容切换不应无故清掉表情。只有面部网格或相关控制器改变时，才按显式兼容表重映射或恢复 neutral。
- 语音驱动口型是独立的未来扩展，默认关闭。没有音频到口型的映射、驱动和测试，就不能把手动口型称为自动 lip sync。

静态造型脚本若调用 `shape_key_clear()`，不适合直接用作表情版导出。需要固定体型/配装 shape 时，先保存完整原始资产，区分要烘焙的体型键与要保留的表情键；保持后者相对新 Basis 的变形正确。不得统一清空后再声称保留了表情。

## 与工作流结合

1. intake 审查并记录原始 shape key/Morph/面部骨/嘴部网格目录，以及已丢失或不能导出的数据；输出 expressions.json。需要重新取原始 FBX/Unity 源时明确指出，不能只靠静态成品增加一个开关恢复丢失的变形数据。
2. appearance 保留脸、眼皮、虹膜、嘴/牙/舌头的对应关系和材质边界；rig 检查面部骨和变形目标的坐标/权重；其它阶段继承清单并登记可能的影响。
3. optimization 对 Basis、全部发布变形目标和受影响网格一起优化；compile 检查真实 Morph/控制器/骨骼或网格组输出并建立名称映射。
4. validate 至少检查 neutral、每个单目标、中间值/极值、常用叠加、张嘴/闭眼的牙舌和眼球遮挡、换装/妆容后的表情保持。骨骼表情和目标变形叠加也需检查。
5. runtime adapter 需要实现有效值限制、默认值、切换/混合规则和重生恢复；多人可见是否需要同步要核实并记录。若只有服务端插件或别的接口能控制，交付真实依赖与调用方式，不编造控制台命令。

各阶段使用自己的 `stages/<stage>/expressions.json`，从前一阶段复制后更新并保存快照，不能修改以前已完成的输出。`reserved / authored / compiled / runtime_verified` 分项推进，离线通过与用户游戏检查分开；当前用户仍负责游戏测试。

## 表情数据也计入体积优化

- 共享同一个基础脸网格，优先存必要的变形增量；一个表情不复制整个人物或整套衣服。嘴部网格替换只增加必要的局部网格。
- 保留需要发布的目标；重复/不用的目标可以去掉，但不能把被组合表情间接引用的目标误删。缩放、合并网格、顶点重排、焊接、减面必须同步映射所有变形目标；没有可靠的对应算法时先保护脸部拓扑，优化其它部分。
- 不以 neutral 好看作为唯一减面依据。保留嘴唇闭合、眼皮边缘和口腔轮廓，量化变形后误差；处理法线变化、材质边界和多个目标混合，不追求只在静态截图中变小。
- 记录基础网格字节、全部 Morph/面部骨/嘴部备选网格数据、每新增目标的增量和总包增量；运行时可测开销另列。未使用的控制器/隐藏嘴仍可能占包大小，不能从文件预算里忽略。
- 不产生“衣服×妆容×瞳色×表情×嘴型”的完整资源副本。与 wardrobe 的 size_budget 共用一个总包预算，按资源并集计数；预算没定或开销没测时填 null，不填 0。

后续补实现时保持稳定 ID 和 schema_version，记录导出/编译/运行时各自缺什么。网格元数据装配与减面算法需要针对带 Morph 的真实输出重新验证，不能直接放宽原有检查。
