# 验证与交付

## 输入身份与不可变基线

保存源模型、编译模型、材质、贴图、工具版本及 SHA256。默认安装目录相同哈希仅证明该文件，不能证明游戏当前没从其他包挂载。询问版本的目的在于消除分支差异，不以用户自行合并补丁为由责怪用户。

候选在独立目录制作。采用硬链接节省空间时，每个待写文件先拆链接；编译器可能重编依赖，保护范围包含输出材质、贴图与模型，不能只保护源 VMDL。编译前后复验基线哈希。

## 预先制定允许差异

- 纯材质候选：网格、命名蒙皮、骨架、挂点、约束、物理应保持。
- 纯物理参数候选：保护渲染属性、骨架层级、材质、第一人称、非目标物理控制；变动应落入指定目标。
- 层级/轴向候选：骨重排允许，但绑定世界位置/基底、命名权重、拓扑与动画跟随需要重新核验。
- 临时去 Jiggle：编译器可能取消对应骨物理标志、重建 PHYS 索引/树；按名字比对未改节点与约束，而不是硬要求所有 DATA 字节相同。
- 源节点父级或无用通道清理：若功能块完全相同而只变 RED2，应明确不产生运行效果修复。

## 编译检查

退出码、完整日志、生成文件存在、时间与哈希都要检查。分类记录 error、warning、权重裁剪等信息，不能说“零问题”而隐藏信息级的实际退化。成功标记只能在断言完成后输出。

`Bad parent node` 类警告：依据当前节点注册信息核对合法父级，不仅因为编译成功就忽略。例如检查 `ClothParams` 时，应查当前工具允许的容器节点，而不是仅凭节点名将其挂到根部。修正父级后比较功能数据；若仅编译元数据改变，不能称其修好了运行抖动。

## 块级与语义回归

先比较实际块清单和字节。块名可能重复，也可能有多组 MDAT/缓冲；不要用单个字典值丢掉同名块。

随附块检查脚本针对资源头版本 12 的基本块目录，并使用合成样本测试；同名块按出现次序编号。它只给出“哪里变了”，不把 RED2 自动忽略，也不把 PHYS 允许变化当作物理通过。真实资源需单独核对兼容性。

继续解析真实数据：

- 渲染：三角形方向、position、normal、tangent/handedness、UV、材质分配和命名蒙皮。网格拆分/重排时按属性与拓扑匹配，避免只对数组索引。
- 骨架：名称、父级、绑定矩阵、remap、蒙皮映射、约束顺序、挂点、hitbox 与动画引用。
- 物理：节点身份、固定/动态分类、初始姿态、质量、段长、动态父级、约束、碰撞、风场与全局设置。
- 非目标项：合同中明确保护的视角、部件、材质及依赖闭包必须独立检查。

未知差异先调查，不修改验证器把它放过。编译可能导致位置舍入或切线变化；仅在有逐点证据、来源解释、受影响材质和误差上限时记录狭窄例外。切线例外对平面法线材质与有法线/各向异性材质风险不同，不能一概忽略。

## 装载与包完整性

ERROR 占位模型先查目标路径、真实编译资源、依赖、预载/驻留、缓存和补丁兼容性，不先重做几何。解析 RERL 递归收集实际材质/纹理依赖，基础游戏外部动画单列；循环去重，缺失引用明确失败。

交付完整包或明确写出补丁基线/必需底包。不同版物理或 LOD 补丁可能覆盖新模型并还原旧物理；不能因为文件能合并就宣称兼容。诊断包和恢复包明确先后，不要求一起覆盖。

归档后检查 CRC、成员路径与逐文件 SHA256 读回。重新打包和复制不可代替依赖验证。交付记录包含：

```text
候选标识、时间、源与成品哈希、基线
用户目标、实际改动、刻意未改项
源检查 / 编译 / 离线回归 / 游戏反馈（分别记）
已知限制、失败试验、包完整或补丁、所需底包
简短测试方法、恢复对象及覆盖范围
```

历史反馈追加，不把“后来失败”静默改写成从来没做过，也不把模糊肯定扩展成所有子系统验收。

## 清理历史资产

只在用户要求时清理。先盘点目录、真实字节、硬链接/联接关系、最近候选和用户指定接受版，追溯其底包、源资产与构建依赖。版本号高不代表更重要；旧补丁需要的底包不能按日期顺手删掉。

永久删除前确定精确目标、解析路径仍在授权范围，默认保留原素材、必要源工程、接受版、恢复依赖、日志与哈希。报告实际移除内容和可恢复性。仅剩脚本不等于还可完整回退。

硬链接共享同一载荷，删除一份路径的逻辑大小不等于磁盘已释放字节。报告逻辑删除量与实际可确认释放量时分开计量，不用目录累加量冒充腾出的空间。
