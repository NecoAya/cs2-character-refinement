# 输入审查、造型与材质迁移

## 锁定素材与工具

按 [阶段合同](stages.md) 建立当前项目清单：原工程/预制体、FBX/Blend/DMX、网格、骨架、衣服、头发、耳尾、眼睛、贴图、原材质、表情数据、动画兼容模板和参考模型。记录路径、SHA256、来源与使用范围；参考素材只读研究，不默认进入人物交付。

Unity 工程优先按 prefab/场景实例追踪实际使用的对象、材质与 GUID，读取 `.meta` 对应关系。素材目录中同名文件、未实例化服装或隐藏对象不能当成默认造型。源有多个比例/配装 shape key 时，记录当前值并区分体型烘焙与保留的表情；保留原工程副本。

列当前工具版本和实际能力：DCC 导入/导出器、Workshop Tools、资源解析器、编译入口。只用本地已支持的参数和合法 ModelDoc 节点类型；没有真实转换工具时先完成清单与适配计划，不输出一个空 DMX 声称成功。

## 单位、坐标与编辑场景

记录长度单位、全局缩放、角色前方/上方、骨局部基底和绑定姿态。用角色身高、关节位置和明确参照点检查缩放，不能仅看贴合截图。导入器对轴的转换和 export 的转换分别记录，避免应用两遍。

原始骨架、网格/材质边界、UV、顶点法线、切线和形态键目录保留到可编辑场景。服装与身体比例调整需同步绑定、附件、袖口、身体遮挡、碰撞和 hitbox；不能只缩放衣服几何而保留旧绑定。重大坐标修改先建立局部小样并验证源→导出→编译变换。

删除组件依据用户造型目标和实际对象/面组，输出删除清单。若未来有换装，只删除当前发布组合确实不用的内容，原资产和可选边界留存；见 [换装](wardrobe.md)。

## 材质迁移合同

逐材质记录源 shader、底图、颜色、附加颜色层、遮罩、透明模式、双面、法线强度、粗糙度/金属度、MatCap 和自发光。原 shader 与 CS2 shader 的字段不是一一对应；对不能迁移的层，说明烘焙、近似和外观代价。

保留脸、眼睛、身体、手、指甲、织物、金属等可独立调节的边界。少 draw call 与可编辑性需要平衡，不能为合材质把应有的材质语义混为一块。局部修色时追踪原 UV/遮罩，不改变相邻区域；只修指甲时定位对应面组。

颜色图、线性遮罩、法线向量与通道打包分别处理。检查导出路径、shader 有效输入、编译纹理格式及解码像素；原图有 alpha、AO 或金属层，不代表最终 shader 实际使用。数值表示与遮罩运算检查见 [材质与优化](materials-and-optimization.md)。

自发光颜色、强度、材质流动、几何自转分别登记：可见 bloom 还受游戏后处理影响。动画附件需要真实骨/动画/运行时驱动，以及正确局部中心和轴，静态图只能证明造型。

## 阶段输出与预览

至少输出素材/工具清单、选择配置、可编辑场景、材质映射、原数据保留说明、删除组件清单和验证记录。真正供下游使用的文件进入该阶段 `outputs`，以获得文件快照；仅写路径清单不会备份指向的文件。

造型预览包含正、侧、背、脸和关键附件近照；首饰可增加佩戴与独立特写。说明预览来源是 DCC、ModelDoc 还是游戏，保留同角度光照/曝光用于前后对比。生成概念图只用于设计，不作为真实导出/游戏效果验收。

开始骨架阶段前检查：比例/坐标、默认显示组合、UV、颜色层、alpha、法线方向及表情保留。用户指定造型检查点时等待实际反馈；否则根据已明确目标继续制作，将待游戏观察项留在报告中。
